# Part 2 (RQ2) · Cross-modal fusion

## The question and the design

**Research question.** Which strategy best combines text, graph and structured evidence into one context for the answer model?

Fusion decides *how* evidence is presented, not *what* is retrieved. To isolate it completely, every fusion method receives the **byte-identical cached evidence bundle** of each question and may not retrieve anything new.

Table: RQ2 design {w=1.6,4.6}
| Element | Setting |
|---|---|
| Cohort | 24 frozen evidence bundles = 8 multi-source families (TG, TS, GS, TGS; 2 each) × 3 variants (normal, noisy, conflict). Unanswerable variants are excluded because there is nothing to fuse for them. |
| Bundles | Frozen from the retrieval-only B4 closeout: for each question the top-5 evidence of the text (B1), graph (B2) and structured (B3) retrievers, plus the variant's stress overlay items, partitioned once into three source lists without changing any source's ranking |
| What changes | Only how the three evidence streams are aligned, selected and combined |
| Budget | 24,000 characters |
| Model calls | Every role (answer, selector, per-source reasoning, fusion, repair) uses the shared model and the 1,024-token cap |
| Runs | 5 methods × 24 bundles = 120 records; 0 errors |

#### Supportability, computed before any call

Fusion can only combine what retrieval found. Before any RQ2 model call, each bundle was classified from its evidence and gold set (evaluator side only): **{{RQ2.support.FULLY_SUPPORTABLE}} fully supportable** (every correct paper is the canonical paper of some evidence item), **{{RQ2.support.PARTIALLY_SUPPORTABLE}} partially supportable** (at least one is) and **{{RQ2.support.UNSUPPORTABLE}} unsupportable** (none is). For two thirds of the bundles the best possible behaviour of any fusion method is therefore a correct abstention.

## The five strategies

### CF-B0 · raw concatenation (control)

Write all evidence items one after another in source order (text, then graph, then structured), each item whole, and stop when the next item would exceed the 24,000-character budget. One answer call.

@figure figures/m_cf_b0.png | CF-B0 (raw concatenation). | 6.0

### CF-B1 · source-separated sections (control)

Write three labelled sections, TEXT EVIDENCE, GRAPH EVIDENCE and STRUCTURED EVIDENCE, each limited to a third of the budget (7,999 characters including its heading; separators are charged to the total). One answer call. This is the same layout as the fixed context of the baselines.

@figure figures/m_cf_b1.png | CF-B1 (source-separated sections). | 6.0

### CF-01 · KAG-inspired entity alignment

**Origin.** KAG (knowledge-augmented generation) links knowledge-graph entities and source text chunks through mutual indexing. The adaptation uses only the alignment principle: evidence about the same entity is grouped together before the context is written. No model invents entities.

**Algorithm.**

1. **Resolve each evidence item to an entity,** in a fixed order: (a) an explicit entity ID on the item; else (b) exactly one match of its exact normalised alias in the registry; else (c) a registry lookup that accepts an ambiguous alias only if exactly one candidate has the item's own entity type (setting S2). Items that still do not resolve form their own **UNALIGNED** group, keyed by evidence ID.
2. **Group** items by entity, keeping retriever order inside each group.
3. **Order groups** by their best member relevance (descending), then by the number of sources they cover (descending), then by entity ID.
4. **Write** each group as `[ENTITY id | display name] [TEXT] [GRAPH] [STRUCTURED] [PROVENANCE]`, using the registry's display name (setting S3).
5. **Pack** complete groups until the budget is full; a next group that only partly fits contributes its highest-ranked items and is flagged `group_truncated`.
6. If no entity resolves at all, fall back to the CF-B1 layout.

**Behaviour in the study.** Every evidence item resolved by its explicit ID; the registry lookup was used {{RQ2.diag.CF-01.global_resolver_uses}} times, no group was truncated and no fallback occurred. CF-01 wrote the largest contexts ({{RQ2.CF-01.context_characters}} characters).

@figure figures/m_cf_01.png | CF-01 (KAG-inspired entity alignment): resolve every item to an entity, group by entity, order groups and write them whole. | 6.0

### CF-02 · SAG-inspired dual-path selection

**Origin.** SAG (SQL-retrieval augmented generation with query-time dynamic hyperedges) combines a structural path and a semantic path. The adaptation treats graph and structured items as *structural* candidates and text items as *semantic* candidates, lets the model choose the structural items that work best together, and fills the rest with text.

**Algorithm.**

1. Split the bundle into structural candidates (graph and structured items) and semantic candidates (text items); remove duplicates by evidence ID and provenance overlap.
2. Build a **compact manifest**: one line per structural candidate, `ID | source | relevance score | first 200 characters of its content | provenance paper and entity IDs`, in input order until the next line would exceed 5,000 tokens (settings S4 and S5).
3. **Selector call:** one model call returns JSON `{"selected_ids": [...], "reason": "..."}` with at most 5 structural items that best answer the question together. Invalid and duplicate IDs are removed.
4. If the output is not valid JSON, one schema-repair call is allowed; if it still fails, the 5 structural items with the highest relevance scores are used (`selector_fallback = relevance`).
5. **Semantic fill:** add text items in retriever order until there are 10 items in total (all items if fewer exist).
6. **Trim** to the budget, removing the lowest-ranked text fill first, then the lowest-priority structural items.
7. One answer call over the selected items.

**Behaviour in the study.** The selector picked only {{RQ2.diag.CF-02.mean_selected}} structural items per bundle on average, with {{RQ2.diag.CF-02.invalid_ids}} invalid IDs and no fallback. As a result CF-02's contexts kept every text item but no graph item and few structured items (graph coverage {{RQ2.CF-02.coverage_graph}}, structured coverage {{RQ2.CF-02.coverage_structured}}): its context was mostly the text evidence.

@figure figures/m_cf_02.png | CF-02 (SAG-inspired dual-path selection): a one-call model selector chooses up to five structural items; text fills the remaining slots. | 6.0

### CF-03 · MegaRAG-inspired late fusion

**Origin.** MegaRAG reasons over each modality separately and then fuses the source-specific results. The adaptation keeps that late-fusion structure with grounded intermediate findings.

**Algorithm.**

1. For each non-empty source, in the order text, graph, structured, make one **reasoning call** that sees only that source's evidence (its CF-B1 section, up to 8,000 characters) and returns JSON `{candidate_answer, supporting_evidence_ids, confidence}`. A source may support only part of the question's conditions.
2. **Validate** the supporting IDs against that source's own evidence. If a source's call fails, that source becomes `ERROR_NO_EVIDENCE`; the others are unaffected. An empty source gets a static `NO_EVIDENCE` finding without a call.
3. **Fusion call:** one call receives the findings and, for every supporting evidence ID, its paper ID, and returns the final answer. The final answer may cite only papers supported by the findings.
4. If the fusion call fails it is retried once with the identical request; a second failure is an error.

**Behaviour in the study.** {{RQ2.CF-03.llm_calls}} model calls per bundle on average; {{RQ2.diag.CF-03.source_statuses.OK}} source findings were grounded and {{RQ2.diag.CF-03.source_statuses.NO_EVIDENCE}} sources had no evidence; the fusion call never needed a retry. Its final fusion context is tiny ({{RQ2.CF-03.context_characters}} characters) because it holds findings, not evidence.

**Every method returned an empty answer on all 24 bundles**, so answer F1 and exact match are 0.000 for all of them and answer quality cannot separate the methods. The methods differ only in cost and in how early a correct paper appears in their evidence ranking:

- **CF-B1 is the cheapest and fastest** ({{RQ2.CF-B1.input_tokens}} input tokens, {{RQ2.CF-B1.latency}}) and the **only Pareto-optimal** method.
- **CF-B0** uses {{RQ2.CF-B0.input_tokens}} input tokens ({{RQ2.diff.input_tokens.CF-B0:CF-B1}} relative to CF-B1): raw concatenation fills the budget with text first, while CF-B1 cuts the text section at a third of the budget (text coverage {{RQ2.CF-B0.coverage_text}} against {{RQ2.CF-B1.coverage_text}}).
- **CF-01** writes the largest contexts ({{RQ2.CF-01.input_tokens}} input tokens): grouping adds entity headers and provenance to every group.
- **CF-02** needs two calls ({{RQ2.CF-02.latency}}) and ends up with a mostly-text context; its MRR is {{RQ2.CF-02.mrr}}: no correct paper appears in its ranked evidence.
- **CF-03** ranks a correct paper earliest (MRR {{RQ2.CF-03.mrr}} against {{RQ2.CF-B1.mrr}} for CF-B1) but needs {{RQ2.CF-03.llm_calls}} calls and {{RQ2.CF-03.latency}} per bundle.

## Why every answer was empty

@figure figures/c_rq2_support_tokens.png | Left: only 2 of the 24 bundles contain every correct paper and 16 contain none. Right: total tokens per question by source combination; CF-02 is cheapest on two-source questions and CF-B1 on three-source questions. | 6.6

- **16 bundles contain no correct paper.** For these, an empty answer is the best possible behaviour, and every method produced it.
- **6 bundles contain some, but not all, of the correct papers.** On these, too, every method returned an empty answer.
- **The 2 fully supportable bundles are both conflict variants.** Their added evidence contradicts one fact of the correct paper (for example a structured record claiming paper rank 20072 where the condition is "at most 20071"). The prompt tells the model to prefer canonical records over tagged overlays, but on both bundles every method's answer was empty: the model judged that no paper met every condition.

The bundles come from the retrieval-only baseline B4, whose text retriever finds almost none of the correct papers of these exact-phrase questions (Chapter 13). The limit of RQ2 is therefore set by retrieval, before fusion begins.

@figure figures/c_rq2_tests.png | RQ2 paired differences in input tokens, latency and model calls. Several differences point the same way in every family (unadjusted p = 0.008, the smallest possible) but still cannot pass the Holm threshold with 8 families and 7 pairs. | 6.4

Answer F1 and exact match are identical for every pair (all p = 1.000). For cost, several differences are perfectly consistent across all 8 families, for example CF-02 using one more model call than CF-B1 on every bundle and CF-03 using 2.75 more; their unadjusted p-value is 0.008, the smallest the exact test can produce with 8 families, and their Holm-adjusted p-value is 0.055. As explained in Chapter 17, no RQ2 difference could reach Holm significance at 0.05; the cost differences are real in the data but not testable at this cohort size. The descriptive conclusions above rest on the means and on their consistency across families.

## Findings

1. **All five methods returned empty answers on all 24 bundles; answer quality is identical (F1 = {{RQ2.CF-B1.answer_f1}}).**
2. **Even where the correct paper was in the evidence, the model judged that no paper met every condition** (the two fully supportable bundles are conflict variants).
3. **The methods differ in cost:** CF-B1 was the cheapest and fastest and the only Pareto-optimal method; CF-02 needed 2 calls and CF-03 {{RQ2.CF-03.llm_calls}}.
4. **{{RQ2.support.UNSUPPORTABLE}} of the 24 bundles contain no correct paper:** most of the limit comes from retrieval, not fusion.
5. With 8 families, no RQ2 difference could reach Holm significance; consistent cost differences are reported descriptively.
