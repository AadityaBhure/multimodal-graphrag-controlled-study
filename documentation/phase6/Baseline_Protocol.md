# Phase 6 baseline operation

All commands use the project interpreter. The baseline adapters invoke the same `research.experiments.runner.run` as Phase 5; no second experiment engine is introduced.

```powershell
.\.venv\Scripts\python.exe scripts/run_baseline.py --config configs/baselines/B1-offline.json --offline --output artifacts/phase6/my-b1-offline-run
.\.venv\Scripts\python.exe scripts/run_baseline.py --config configs/baselines/B2-offline.json --offline --output artifacts/phase6/my-b2-offline-run
.\.venv\Scripts\python.exe scripts/run_baseline.py --config configs/baselines/B3-offline.json --offline --output artifacts/phase6/my-b3-offline-run
.\.venv\Scripts\python.exe scripts/run_baseline.py --config configs/baselines/B4-offline.json --offline --output artifacts/phase6/my-b4-offline-run
```

The matching `B1.json`–`B4.json` configs enable the approved Groq model; omit `--offline` only when the intended API execution is authorized. The CLI refuses paper_test mode, test/human_test splits, unnamed generation models and more than four API queries per invocation. This cap is not permission to chain many invocations into a large batch. The completed Phase 6 external smoke was exactly four requests explicitly approved by the user. The exact messages and source provenance are in `api_payload_preview/` and the outputs in `groq_smoke/`.

Use a new experiment directory after changes to config, source code, system fingerprint or data versions. Repeat an unchanged command to resume without duplicating completed queries. Error records are terminal and should be reviewed; do not delete them to silently retry paid calls. Default immutable evidence cache is outside canonical data at `artifacts/phase6/cache`. Empty/unsupported source results are not cached. A cache hit is visible in diagnostics and contributes zero new source-retrieval calls. B4 always invokes three source interfaces, including cache lookups; that count is separately logged as `source_invocations`.

B1 loads the frozen 700,244 x 384 exact inner-product index into RAM (about 1.00 GiB for vectors) and maps global paper IDs using the frozen mapping. Query encoding uses the pinned local tokenizer and frozen ONNX weights with CPU float32 execution. No downloads or paper embeddings are generated.

B2 never opens the text FAISS index or abstract view. Its lexical resolution scans graph labels through bounded-memory DuckDB, retains at most 64 candidate labels and selects three semantic seeds. Exact source-name mentions have priority, followed by cosine similarity and node ID. Breadth-first traversal follows only the four official relation types and their explicitly tagged traversal inverses. Depth is two, with at most 2,000 queued/visited nodes, 20,000 scanned edges and 128 edges per node. Candidate paper ordering is path length, seed rank, then global ID. Null names remain null and can be traversed. No seed produces no candidates; it never triggers text fallback. Truncation is recorded.

B3 supports explicit publication-year/date, citation-count, paper-rank, venue namespace/ID/name and document-type predicates. Numeric/date comparisons, bounded ranges and NULL predicates compile to a fixed SELECT with bound values. String equality/inequality is exact. The natural-language parser recognizes documented clauses such as `published after 2018`, `at least 10 citations`, `publication year is between 2010 and 2020`, `citation count is missing` and `venue namespace is journal`. It is not a general NL-to-SQL system. Recognized structured clauses are logged; non-structured requirements cannot be proved by B3 alone. Unsupported disjunction/SQL language yields an explicit unsupported result. The database is attached READ_ONLY; no user-supplied SQL is accepted.

B4 executes the same Text, Graph and Structured retrieval functions independently. It does not share candidate restrictions across sources or intersect their result sets. Source sections are concatenated in Text–Graph–Structured order; each gets a fixed third of the 24,000-character safety cap. Single-source methods get the whole cap. Truncated and omitted evidence IDs are recorded. This is simple fixed-budget serialization, not a context optimization method. Its aggregate ranking is first-occurrence source-order concatenation; therefore Recall@5 refers to the first five positions (usually Text), while gold coverage captures the whole union.

Generation is identical across methods: `openai/gpt-oss-120b`, temperature 0, reasoning effort low, 1,024 maximum completion tokens, per-query seed, JSON object output and one common grounding prompt. The prompt permits only IDs visible in context and requires support for all requested conditions. Strict parsing rejects hallucinated IDs, booleans, strings masquerading as IDs and malformed objects. Provider input/output usage is recorded; absent measurements remain NULL. No pricing source was configured, so monetary cost estimates remain NULL.

Canonical source stores and existing benchmark files are read-only. Noise/conflict evidence is appended only to the evaluation stream, tagged with overlay provenance and kept source-specific. Graph overlays cannot inject papers outside B2's graph-selected candidate set. Contradictory facts never replace canonical data. Any future change to these controls or prompt must be versioned as a distinct experiment, not silently applied to a baseline.
