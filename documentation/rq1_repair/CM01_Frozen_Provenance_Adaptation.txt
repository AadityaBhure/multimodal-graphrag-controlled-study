CM-01 PROVENANCE ADAPTATION — FROZEN REPAIR DECISION
The missing STaRK source-chunk provenance is acknowledged.
Do not invent a mapping from STaRK graph relations to paper abstract/text chunks.
STaRK provides authoritative graph edges but does not identify a textual chunk from which each edge was extracted. Mapping relations to arbitrary paper abstracts would create unsupported provenance and would also violate the MMG-STaRK-MAG Graph/Text modality boundary.
Therefore freeze the following dataset-specific CM-01 adaptation and continue the RQ1/RQ2 scientific repair from checkpoint 34c8503.
1. Scientific status of this decision
Phase 1D specifies KG²RAG-style:
semantic source chunks
→ chunk-linked triples
→ graph expansion
→ weighted components
→ maximum spanning trees
→ DFS context
→ reranking

MMG-STaRK-MAG does not contain the paper-to-triple extraction provenance needed for literal chunk_graph_links.
Therefore CM-01 remains explicitly:
KG²RAG-inspired graph-context organization adapted to a native knowledge graph without source-text extraction provenance.
It must never be described as an exact reproduction of KG²RAG.
The adaptation must preserve:
- semantic seeding;
- graph expansion;
- query-conditioned edge weights;
- connected components;
- maximum spanning tree organization;
- deterministic DFS;
- cross-encoder component ranking;
- evidence deduplication;
- context-budget enforcement.
The only substituted concept is:
original source text chunk

becomes:
canonical graph provenance unit

2. Define Canonical Graph Provenance Unit
For CM-01 only, define a deterministic object:
GraphProvenanceUnit

with at least:
unit_id
canonical_edge_id
relation_type
source_node_id
target_node_id
source_node_type
target_node_type
source_label
target_label
serialization
derived_inverse
canonical_official_edge_id
provenance

A provenance unit corresponds to one authoritative graph relation, not to a Text-view document.
It is not a fabricated fact.
It is a deterministic serialization of an existing STaRK relation.
3. Canonical relation serialization
Use only Graph-view information.
Never include:
- paper abstract;
- paper full text;
- structured publication year;
- citation-count attribute;
- rank;
- venue metadata;
- document type;
- any SQL-derived value.
Paper title is allowed, because MMG-STaRK-MAG already froze paper title as the Graph-view semantic label.
Missing labels must remain missing semantically.
If a label is NULL, serialize the stable entity ID/type rather than inventing a name.
Freeze relation templates as follows.
WRITES
For:
AUTHOR --WRITES--> PAPER

serialize:
Author <author_label_or_id> writes Paper <paper_title_or_id>.

AFFILIATED_WITH
For:
AUTHOR --AFFILIATED_WITH--> INSTITUTION

serialize:
Author <author_label_or_id> is affiliated with Institution <institution_label_or_id>.

CITES
For:
PAPER_A --CITES--> PAPER_B

serialize:
Paper <paper_A_title_or_id> cites Paper <paper_B_title_or_id>.

HAS_TOPIC
For:
PAPER --HAS_TOPIC--> FIELD_OF_STUDY

serialize:
Paper <paper_title_or_id> has topic <field_label_or_id>.

No additional natural-language inference is permitted.
4. Critical citation mapping decision
A citation edge:
PAPER_A --CITES--> PAPER_B

maps to its own graph provenance unit.
It does NOT map to:
- PAPER_A's abstract;
- PAPER_B's abstract;
- an arbitrary text chunk from either paper.
Its source representation is only:
Paper A title/ID + CITES + Paper B title/ID

together with authoritative edge provenance.
This prevents Text leakage.
5. Critical author-affiliation mapping decision
An affiliation edge:
AUTHOR --AFFILIATED_WITH--> INSTITUTION

also maps to its own graph provenance unit.
It must NOT be assigned to every paper written by the author as a fake source chunk.
In particular, do NOT construct:
paper abstract
→ author affiliation edge

provenance.
The paper relationship is recovered naturally through graph topology:
PAPER
← WRITES —
AUTHOR
— AFFILIATED_WITH →
INSTITUTION

Thus:
- WRITES has its own provenance unit;
- AFFILIATED_WITH has its own provenance unit;
- the graph structure connects them;
- no unsupported paper-text provenance is fabricated.
6. Derived inverse traversal edges
MMG-STaRK-MAG contains official directed edges plus derived inverse traversal entries.
A derived inverse edge must not create a second semantic provenance unit.
For example:
AUTHOR --WRITES--> PAPER

and its derived traversal:
PAPER --WRITTEN_BY--> AUTHOR

refer to the same authoritative relation.
Therefore:
derived inverse traversal
→ canonical official edge
→ same GraphProvenanceUnit

Preserve:
derived_inverse = true

in traversal diagnostics.
Deduplication operates on the canonical official relation/provenance-unit ID.
Do not count official + inverse traversal as two independent evidence facts.

Document exactly how it is constructed.

9. CM-01 semantic seeds under this adaptation
Within the shared candidate graph:
1. construct the canonical GraphProvenanceUnit for every canonical candidate relation;
2. embed its frozen graph-only serialization using the unchanged global MiniLM embedder;
3. embed the query using the same global embedder;
4. compute cosine similarity;
5. select:
k_seed = 10

highest-scoring provenance units.
These are the adapted equivalents of KG²RAG's semantic seed chunks.
Tie-break deterministically by canonical provenance-unit ID.
Do not use abstracts.
10. One-hop expansion
From entities touched by the ten seed provenance units:

m_hops = 1

expansion inside the already frozen candidate graph only.
Every expanded relation must resolve to its canonical GraphProvenanceUnit.
No external graph fetch is allowed.
11. Query-conditioned edge weight
For every expanded canonical relation e:
weight(e) =
cosine(
    query_embedding,
    embedding(GraphProvenanceUnit.serialization)
)

This replaces Phase 1D's unavailable:
similarity(query, original source text chunk)

and is the one frozen dataset adaptation.
Do not substitute another scoring function.
12. Component and tree construction
Continue literal Phase 1D organization after the provenance substitution:

↓

↓
MAXIMUM SPANNING TREE for each component

Weight is the cosine score defined above.

If exact equivalence holds, it may remain as an implementation-equivalent formulation and must be documented.

Freeze deterministic tie-breaking.
13. DFS organization
For each component tree:
- choose the highest-weight tree edge as the traversal root;
- deterministically resolve ties;
- DFS the tree;
- when a canonical relation is first encountered, append its GraphProvenanceUnit serialization once;
- never duplicate the same canonical provenance unit.
This is the adapted text_representation(T_i).
It remains graph evidence because it consists exclusively of graph-native relation serializations.
